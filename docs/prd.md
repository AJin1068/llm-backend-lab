## 1. 개요

맞벌이 부부의 연말정산 자료로 "어떤 공제를 누구에게 넣으면 부부 합산 환급액이 가장 큰가"를 계산해 보여주고, 그 근거 조문을 함께 제시하는 AI 에이전트예요. 연말에는 "남은 기간에 무엇을 누구 명의로 하면 환급이 늘어나나"도 순효과 순으로 제안해요.

## 2. 풀려는 문제

- 맞벌이 부부는 부양가족·의료비·카드 같은 공제를 두 사람 중 누구에게 넣을지 고를 수 있고, 어떻게 나누느냐에 따라 합산 환급액이 달라져요.
- 조합을 하나씩 손으로 계산해 비교하기는 번거롭고, "왜 이쪽이 유리한지" 근거를 찾기도 어려워요. (홈택스가 부부 배분 비교를 어디까지 제공하는지는 확인 필요)
- 부부가 같은 공제를 둘 다 넣는 중복공제 실수도 생겨요.
- 연말 전에는 "남은 기간에 무엇을 누구 명의로 하면 환급이 늘어나나"가 궁금하지만 답해주는 곳이 마땅치 않아요.

## 3. 목표

| 목표 | 내용 |
| --- | --- |
| 제품 목표 | 부부 합산 환급액이 최대인 배분안을 근거 조문과 함께 보여주고, 연말 절세 행동을 순효과 순으로 제안한다. |
| 포트폴리오 목표 | LLM 백엔드 면접에서 "무엇이 깨졌고, 어떻게 재고, 고쳐서 숫자가 얼마나 바뀌었나"를 두 주제(평가 하네스·툴 호출 신뢰성, Kotlin 게이트웨이)에서 말할 수 있게 한다. |

## 4. 대상 사용자

- 2025년 귀속(2026년 1~2월에 하는 연말정산) 맞벌이 근로소득자 부부.
- 데이터는 전부 가상 가구예요. 실제 개인 데이터는 쓰지 않아요(발표용 PDF도 가상 가구로 만듦).

## 5. 범위

| 할 것 (v1, ~11/22) | 안 할 것 |
| --- | --- |
| 공제 5그룹: 부양가족(기본·추가), 자녀세액공제, 의료비, 교육비, 카드 | 보험료·기부금 등 5그룹 밖 공제 |
| 가능한 배분 전부 비교 + 중복공제 검사 | 근로소득 외 소득(사업·금융 등), 맞벌이 아닌 가구 |
| 간소화 PDF 업로드 → 공제 항목 추출 (v1은 단순한 방법 하나, 막히면 JSON 업로드) | 실제 홈택스 연동, 신고 대행 |
| 대화형 에이전트 + React 화면(6장 화면 요구사항) + 근거 조문 | LLM이 직접 세금을 계산하는 것 |
| 평가 하네스와 11/22 기준 수치 | LangChain, Kafka |
| (3주차) Kotlin 게이트웨이, 연말 절세 시뮬레이터 | 세법 지식을 모델에 학습(파인튜닝)시키는 것 |
| | 지출을 늘리라는 제안 |

**연말 절세 시뮬레이터**: 행동 후보는 3개로 제한해요. 카드 공제 문턱(결제 수단·명의), 연금저축·IRP, 의료비 몰기예요. 정렬 기준은 순효과(아낀 세금 − 추가 지출)예요. 문턱 비율·한도 같은 숫자는 규칙표에 넣기 전에 2025년 귀속 자료로 확인 필요.

## 8. 성공 기준

| 기준 | 어떻게 확인하나 | 목표값 |
| --- | --- | --- |
| 계산기가 맞다 | 국세청 책자 사례·홈택스 모의계산 결과와 결정세액 일치 | 수집한 사례 전부 일치 |
| AI가 대화를 잘한다 | 가상 사용자 대화 후 배분안이 기준 정답과 같은 비율 | 미정. 11/22 기준 수치를 보고 정함 |
| 근거가 맞다 | 맞는 조문을 찾아온 비율, 다른 연도 조문이 섞인 횟수 | 미정 |
| 서비스가 버틴다 | AI 호출에 일부러 장애를 낸 동안 평가 하네스 성공률 | 미정. 게이트웨이 전/후 비교로 제시 |
| 발표에서 완성된 서비스로 보인다 | 데모 흐름 끝까지 완주: PDF 업로드 → 대화 → 배분안 비교 → 근거 조문 → 절세 카드 | 11/27 발표에서 끊김 없이 완주 |

목표값을 미리 정하지 않은 이유: 재기 전에 숫자를 정하면 근거 없는 숫자가 돼요. 11/22에 "고치기 전" 수치를 잰 뒤 개선 목표를 정해요.

## 10. 미정 사항과 확인 필요

**정해야 할 것**

- 성공 기준의 목표값 (11/22 기준 수치를 본 뒤)
- 하루짜리 LangChain 비교 버전을 만들지 (ADR-0001)
- SLM·파인튜닝 실험을 할지, 한다면 언제 (12월 이후 후보)
- 세무사에게 가상 가구 몇 개를 검토받을지 (비용은 견적 필요)
- 폴백 모델 조합 (게이트웨이 단계, 11/23~). 모델 역할 배분은 ADR-0006에서 정함

**사실인지 확인해야 할 것**

- 2025년 귀속 연말정산 안내 책자의 가구 전체 계산 사례 수
- 국세청 질의회신을 어디서 얼마나 모을 수 있는지
- 홈택스 모의계산·미리보기 제공 범위, 부부 배분 비교 기능 유무
- 간소화 PDF 형식(텍스트 추출 가능 여부)
- 2025년 귀속 공제율·한도·카드 공제 문턱 비율
- 연금저축·IRP 세액공제 한도와 공제율
- AI 회사별 호출 제한(레이트 리밋)과 단가
- 실제 간소화 PDF가 글자를 그대로 담은 표인지 (추출 방법 선택에 영향)
- Upstage Document Parse 가격과 무료 크레딧 (시나리오③)

## 부록. 용어 풀이

| 용어 | 쉬운 말 | 이 서비스에서는 |
| --- | --- | --- |
| 계산 엔진(계산기) | LLM 없이 코드로 세금을 계산하는 부분 | "어머니 공제를 아내가 받으면 부부 환급액이 얼마"를 계산 |
| 최적화 | 가능한 배분을 다 계산해 환급액이 가장 큰 것을 고르기 | 의료비·부양가족을 누구에게 넣을지 정답 고르기 |
| 툴 호출(도구 호출) | AI가 직접 계산하지 않고 계산기 같은 코드를 불러 쓰기 | AI가 계산기에 가구 정보를 넘기고 결과를 받음 |
| 에이전트 하네스 | 모델에게 도구를 쥐여주고, 호출을 검사·실행하고, 몇 번까지 돌지 정하는 틀 (일을 시키는 쪽) | agent/의 AI 호출 루프 |
| 평가 하네스 | 에이전트를 통째로 감싸서 자동으로 채점하는 틀 (채점하는 쪽) | 가상 가구 시나리오(v0는 10개)로 AI를 돌려 정답률을 잼 |
| 가상 사용자 | 정답 정보를 쥐고 AI와 대화하는 가짜 사용자(이것도 AI) | "어머니 연소득 없음"을 알지만 물어봐야만 대답함 |
| 기준 정답 | 검증된 계산기에 진짜 가구 정보를 넣어 나온 답 | AI가 대화로 도달한 배분안과 비교하는 기준 |
| 홀드아웃 | 개발 중에 일부러 안 보는 시험용 시나리오 | 레포와 이 프로젝트 밖(맥북)에만 둠 |
| 검증 세션 | 개발 중에만 있는 별도 Claude 대화. 채점하는 쪽 | 숫자가 나오는 PR(5, 15, 17, 19, 21)만 다시 재고 리뷰 |
| 서비스 안 검증 에이전트 | 서비스가 돌 때 판정·근거를 다시 보는 제품 코드. 채점받는 쪽 | 메인 에이전트의 배분 판정과 근거 조문을 재검토 |
| 가이드 / 센서 | 가이드 = AI가 움직이기 전에 방향을 잡는 것, 센서 = 움직인 뒤 결과를 검사하는 것 | 프롬프트 지침(가이드) + 답의 금액 검사(계산형 센서) |
| RAG | 문서를 검색해서 근거를 찾아 AI에게 주는 방식 | "왜 아내가 유리한가"에 붙일 2025년 조문 찾기 |
| 게이트웨이 | 우리 서버와 AI 회사 사이의 중간 관문 서버 | AI 호출 비용 기록, 실패하면 다른 모델로 넘기기 |
| 레이트 리밋 | 일정 시간에 보낼 수 있는 호출 수 제한 | AI 회사가 거절하기 전에 우리가 먼저 속도 조절 |
| 서킷브레이커 | 계속 실패하는 곳에 잠깐 호출을 끊는 장치 | AI 회사 서버가 죽으면 기다리지 않고 바로 다른 모델로 |
| SSE | 서버가 답을 조금씩 흘려보내는 방식 | AI 답변이 한 글자씩 화면에 나타남 |
