# ADR-0002. 에이전트는 Python, LLM 게이트웨이는 Kotlin 별도 서비스로 나눈다

- 상태: 승인됨
- 날짜: 2026-11-11
- 결정자: 서아진

## 맥락

계산 엔진·에이전트·평가·RAG는 Python 생태계가 편하다. 반면 4년 Kotlin/Spring 경력을 보여줄 자리가 필요하고, 플랫폼 쪽 직무에서는 "AI 호출이 안정적으로 돌게 하는 서버"를 묻는다.

## 결정

에이전트 핵심은 Python(FastAPI), LLM 게이트웨이는 Kotlin(Spring) 별도 서비스로 둔다. 한 레포(`taxsplit`, 서비스 이름은 원투원)에 `agent/`, `gateway/`, `eval/` 폴더를 둔다. 둘 사이 경계는 HTTP 하나다. Kafka는 쓰지 않는다.

## 검토한 대안

- Python 단일: 빠르지만 Kotlin 경험을 보여줄 자리가 없다.
- Kotlin 중심: 강점 언어지만 평가·RAG 도구를 직접 만들 일이 늘어난다.
- 게이트웨이를 별도 레포로: PR 하나에서 양쪽을 같이 고칠 수 없고, 데모를 한 번에 띄우기 어렵다.

## 결과

- 좋은 점: 레이트 리밋·서킷브레이커·폴백 같은 Spring 경험을 그대로 살린다. AI 호출 주소를 설정값으로 두어 게이트웨이 없이도 Python만으로 돈다. 게이트웨이가 HTTP로만 이어져 "어떤 서비스에도 붙일 수 있다"를 구조로 보인다.
- 나쁜 점: 두 언어·두 서비스를 배포·테스트해야 한다. 호출이 한 번 더 거쳐 가니 응답 속도가 조금 느려질 수 있다(k6 부하 테스트로 잰다).
